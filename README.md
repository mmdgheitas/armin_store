# آرمین استور — فروشگاه اینترنتی فارسی

یک فروشگاه اینترنتی کامل و آماده‌ی بهره‌برداری با **Flask** و **SQLite**، طراحی‌شده برای هاست‌های اشتراکی **cPanel / Passenger**. رابط کاربری کاملاً راست‌به‌چپ، تاریخ **شمسی**، واحد پول **تومان** و بدون نیاز به Node.js، Redis یا سرویس جانبی است.

- صفحه فروشگاه: `/`
- پنل مدیریت: `/admin/`
- نصب اولیه: `/setup/`
- سلامت سرویس: `/health`

## امکانات

### فروشگاه (سمت مشتری)

- **کاتالوگ محصول**: دسته‌بندی چندسطحی، برند، تنوع (رنگ/اندازه/…)، گالری تصویر و ویدئو، مشخصات فنی، محصولات مرتبط، برچسب تخفیف و موجودی.
- **جست‌وجو و فیلتر**: جست‌وجوی فارسی، فیلتر دسته/برند/قیمت/موجودی، مرتب‌سازی، صفحه‌بندی.
- **سبد خرید و تسویه**: خرید مهمان و کاربر، کد تخفیف، هزینه ارسال بر اساس استان/شهر، مالیات اختیاری، حداقل مبلغ سفارش.
- **رزرو موجودی ضد رقابت**: هنگام ثبت سفارش موجودی رزرو می‌شود و با اتمام مهلت پرداخت به‌صورت خودکار آزاد می‌شود؛ از فروش بیش از موجودی جلوگیری می‌شود.
- **پرداخت آنلاین**: درگاه **BitPay** با مسیرهای قابل تنظیم، تأیید سمت سرور، جلوگیری از پردازش دوباره‌ی callback و حالت آزمایشی داخلی.
- **پرداخت آفلاین/دستی**: ثبت پرداخت خارج از درگاه توسط مدیر.
- **حساب کاربری**: ثبت‌نام/ورود با موبایل و رمز، ورود با کد یکبارمصرف، بازیابی رمز، نشست امن، قفل موقت پس از تلاش‌های ناموفق.
- **پنل مشتری**: سفارش‌ها و پیگیری وضعیت، آدرس‌ها، ویرایش پروفایل، علاقه‌مندی‌ها، مقایسه محصولات، نظرات، ویدئوهای ارسالی، تیکت پشتیبانی، اعلان‌ها.
- **محصولات دانلودی**: تحویل فایل خصوصی پس از پرداخت، با لینک امن و محدودیت دانلود.
- **محتوا**: وبلاگ، صفحات ثابت (درج در فوتر)، بنر و اسلایدر، نظرات و ویدئوهای تأییدشده.
- **سئو**: عنوان/توضیح متا، Open Graph، `sitemap.xml`، `robots.txt` قابل ویرایش و داده ساختاریافته Schema.org.
- **تجربه کاربری**: فونت وزیرمتن به‌صورت محلی (بدون CDN)، اعداد و تاریخ شمسی، طراحی واکنش‌گرا، حالت تعمیرات.

### پنل مدیریت

- **داشبورد**: فروش امروز/۳۰ روز/کل، تعداد سفارش و مشتری، هشدار کمبود موجودی، نمودار ۱۴ روزه، آخرین سفارش‌ها و پرداخت‌ها.
- **محصولات**: ایجاد/ویرایش/حذف نرم، تنوع‌ها، تصاویر و ویدئو، مشخصات، قیمت خرید/فروش، موجودی و آستانه هشدار.
- **انبار**: مشاهده گردش موجودی، تعدیل دستی با ثبت دلیل و لاگ، گزارش ارزش انبار.
- **سفارش‌ها**: ثبت سفارش دستی، تغییر وضعیت با قواعد مجاز، شماره رهگیری و شرکت حمل، یادداشت داخلی، مرجوعی با بازگرداندن موجودی، لغو، بازپرداخت.
- **پرداخت‌ها**: مشاهده تراکنش‌ها، وضعیت، درگاه و تأیید پرداخت دستی.
- **مشتریان**: مشاهده پروفایل، سفارش‌ها و سابقه خرید، ویرایش و بازنشانی رمز.
- **بازاریابی**: کدهای تخفیف (درصدی/مبلغی، سقف، حداقل سفارش، محدودیت دسته/محصول، ظرفیت و مصرف هر کاربر)، کمپین‌های تبلیغاتی.
- **محتوا**: وبلاگ، صفحات، بنرها، نظرات و ویدئوهای مشتریان (تأیید/رد).
- **پشتیبانی**: تیکت‌ها با پیوست و پاسخ، اعلان‌ها.
- **گزارش‌ها**: فروش، سود، انبار، محصولات و هزینه‌ها با فیلتر تاریخ شمسی و خروجی **Excel / CSV / PDF**.
- **کاربران و نقش‌ها**: ساخت کارمند، نقش سفارشی و مجوزهای دقیق.
- **تنظیمات**: اطلاعات فروشگاه، واحد پول، فروش، آپلود، احراز هویت، پرداخت، پیامک، سئو، امنیت و بکاپ — همراه با ماسک‌شدن مقادیر حساس.
- **بکاپ**: ساخت، دانلود، آپلود و حذف نسخه پشتیبان (دیتابیس + فایل‌های ذخیره‌شده).
- **لاگ رویدادها**: ثبت عملیات مدیریتی و رویدادهای امنیتی مهم.

## پیش‌نیازها

- **Python 3.9 تا 3.13** (تست‌شده روی 3.11)
- **SQLite 3** (همراه پایتون؛ هیچ دیتابیس جداگانه‌ای لازم نیست)
- فضای دیسک برای دیتابیس، تصاویر و بکاپ‌ها
- برای هاست: cPanel با قابلیت **Setup Python App** (Passenger) و **SSL فعال**

بدون نیاز به: Node.js، npm، Redis، Celery، cron اجباری، SMTP اجباری.

## اجرای محلی

```bash
# ۱) ساخت محیط مجازی
python3 -m venv /home/user/venv
source /home/user/venv/bin/activate

# ۲) نصب وابستگی‌ها
pip install -r requirements.txt

# ۳) اجرای برنامه در حالت توسعه
FLASK_ENV=development python app.py
```

سپس:

1. `http://127.0.0.1:5000/setup/` را باز کنید.
2. کلید نصب را از `instance/install_key.txt` (یا متغیر `SETUP_KEY`) بردارید.
3. نام فروشگاه و حساب مدیر کل را بسازید. «نصب داده نمونه» را برای آشنایی سریع فعال کنید.
4. وارد `/auth/login` شوید و از `/admin/` شروع کنید.

> در حالت `development`، کوکی نشست روی HTTP هم کار می‌کند. در `production` به‌طور پیش‌فرض `SESSION_COOKIE_SECURE=1` است و ورود فقط روی **HTTPS** انجام می‌شود.

## نصب روی cPanel

راهنمای گام‌به‌گام و کامل: **[docs/deploy-cpanel.md](docs/deploy-cpanel.md)**

خلاصه:

1. فایل ZIP پروژه را در مسیر **خارج از `public_html`** (مثلاً `/home/USER/armin_store`) آپلود و استخراج کنید.
2. در cPanel → **Setup Python App** یک برنامه با Application root برابر مسیر پروژه، Startup file `passenger_wsgi.py` و Entry point `application` بسازید.
3. وابستگی‌ها را با `pip install -r requirements.txt` در همان محیط مجازی نصب کنید.
4. متغیرهای محیطی (`FLASK_ENV=production`، `SESSION_COOKIE_SECURE=1`، `PREFERRED_URL_SCHEME=https`، …) را تنظیم و برنامه را Restart کنید.
5. مجوز نوشتن برای `instance/`، `storage/` و `backups/` بدهید.
6. `/setup/` را باز کنید، کلید نصب را وارد و حساب مدیر را بسازید.
7. پس از نصب، `instance/install_key.txt` را حذف کنید.

## تنظیمات محیطی

فایل نمونه: [`.env.example`](.env.example). متغیرهای محیطی cPanel اولویت دارند و `.env` فقط مقادیر غایب را پر می‌کند.

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `FLASK_ENV` | `production` | `production` / `development` |
| `SECRET_KEY` | تولید خودکار | در صورت خالی بودن، در `instance/secret_key.txt` با مجوز 600 ساخته می‌شود |
| `DATABASE_PATH` | `instance/store.db` | مسیر مطلق فایل SQLite |
| `INSTANCE_DIR` / `STORAGE_DIR` / `BACKUP_DIR` | کنار پروژه | مسیرهای داده، فایل‌های آپلودی و بکاپ |
| `DATABASE_URL` | — | جایگزین اختیاری (مثلاً Postgres در آینده) |
| `MAX_CONTENT_LENGTH_MB` | `80` | سقف کل حجم درخواست آپلود |
| `SESSION_COOKIE_SECURE` | `1` در production | روی HTTPS باید `1` باشد |
| `PREFERRED_URL_SCHEME` | `https` | پروتکل ساخت لینک‌ها |
| `TRUST_PROXY_HEADERS` | `1` | خواندن IP/پروتکل واقعی از پروکسی cPanel |
| `SETUP_KEY` | — | کلید نصب جایگزین فایل |
| `LOG_LEVEL` | `INFO` | `DEBUG` / `INFO` / `WARNING` / `ERROR` |
| `PORT` | `5000` | فقط اجرای محلی |

## پرداخت، پیامک و پشتیبان‌گیری

### درگاه BitPay

در **پنل مدیریت → تنظیمات → درگاه پرداخت**:

- `bitpay_enabled` را فعال کنید.
- `bitpay_api_key` را از پنل درگاه وارد کنید (در فرم ماسک می‌شود).
- آدرس پایه، مسیر دریافت توکن، مسیر تأیید و آدرس صفحه پرداخت قابل ویرایش‌اند تا تغییرات مستندات درگاه بدون تغییر کد اعمال شود.
- `bitpay_amount_multiplier`: اگر مبالغ فروشگاه تومان و درگاه ریالی است، مقدار `10` مناسب است.
- **حالت آزمایشی** (`bitpay_test_mode`) کل چرخه پرداخت را بدون تراکنش واقعی شبیه‌سازی می‌کند و به کاربر اعلام می‌شود.

آدرس بازگشت (callback) باید دامنه‌ی عمومی و **HTTPS** باشد. پس از هر تغییر، یک سفارش آزمایشی کامل ثبت کنید.

### پیامک

سرویس پیامک سازگار با API الگویی (base URL، کلید، مسیر verify/bulk و کد الگوها) در تنظیمات پیکربندی می‌شود. برای هر رویداد (OTP، ثبت سفارش، پرداخت، ارسال، تحویل، لغو، پاسخ تیکت) می‌توانید الگو و فعال/غیرفعال بودن را تعیین کنید. ارسال‌ها در جدول لاگ پیامک ذخیره می‌شوند. اگر پیامک پیکربندی نشده باشد، OTP در حالت توسعه در لاگ برنامه ثبت می‌شود و فروشگاه از کار نمی‌افتد.

### پشتیبان‌گیری

از **مدیریت → بکاپ** نسخه پشتیبان بسازید و دانلود کنید. فایل‌های بکاپ در `backups/` نگهداری می‌شوند. توصیه می‌شود علاوه بر بکاپ داخلی، از **Backup Wizard** یا **Backup** خود cPanel هم به‌صورت دوره‌ای استفاده کنید.

## امنیت

- رمزها با **PBKDF2-SHA256** و نمک تصادفی ذخیره می‌شوند؛ مقایسه‌ی ثابت‌زمان.
- **CSRF** روی همه فرم‌های تغییردهنده فعال است.
- نشست: `HttpOnly`، `SameSite=Lax` و در production فقط `Secure`.
- محدودیت نرخ درخواست برای ورود، OTP و مسیرهای حساس؛ قفل موقت حساب و سقف تلاش هر IP.
- OTP یک‌بارمصرف با انقضا و سقف تلاش.
- آپلودها: بررسی پسوند، MIME واقعی، امضای فایل، اندازه و ابعاد؛ نام فایل تصادفی؛ فایل‌های خصوصی خارج از دسترس مستقیم وب.
- جلوگیری از Path Traversal در دانلود و رسانه؛ هدرهای `X-Content-Type-Options: nosniff`، `X-Frame-Options: SAMEORIGIN` و CSP.
- پاک‌سازی HTML محتوای کاربر (حذف script/onerror/javascript:).
- کلید نشست و کلید نصب با مجوز `600`؛ مقادیر حساس تنظیمات ماسک می‌شوند.
- همه‌ی بررسی‌های مجوز در سمت سرور انجام می‌شود.

## نگهداری و به‌روزرسانی

1. از دیتابیس و `storage/` بکاپ بگیرید.
2. فایل‌های نسخه جدید را جایگزین کنید (بدون حذف `instance/`، `storage/` و `backups/`).
3. وابستگی‌ها را به‌روز کنید: `pip install -r requirements.txt`.
4. در صورت نیاز به مهاجرت ساختار دیتابیس:
   ```bash
   flask --app passenger_wsgi:application init-db
   ```
   (یا از محیط مجازی cPanel با تنظیم `FLASK_APP=passenger_wsgi.py`).
5. برنامه را Restart کنید (`touch tmp/restart.txt` در ریشه برنامه).

## عیب‌یابی

| نشانه | بررسی |
|---|---|
| خطای 500 | `instance/logs/app.log` و `stderr.log` در ریشه برنامه |
| 503 از Passenger | مسیر Application root، فایل startup و فعال بودن محیط مجازی |
| «دیتابیس قابل نوشتن نیست» | مجوز `instance/` و `DATABASE_PATH` |
| ورود انجام می‌شود ولی خارج می‌شود | روی HTTP، `SESSION_COOKIE_SECURE=0` یا HTTPS را فعال کنید |
| خطای 400 (CSRF) | کوکی‌ها مسدود نشده باشند؛ فرم را دوباره بارگذاری کنید |
| تصاویر 404 | مجوز و وجود `storage/public/...`؛ مسیر ذخیره‌شده در دیتابیس |
| `database is locked` | کاهش عملیات هم‌زمان؛ WAL و `busy_timeout` فعال است، اما SQLite برای ترافیک سنگین مناسب نیست |
| صفحه نصب باز نمی‌شود | وجود `instance/installed.lock`؛ برای نصب مجدد فقط روی نسخه‌ی تازه حذف شود |
